## Collection boundaries

Astro 7 Content Collections use MDX files and Zod schemas in src/content.config.ts. Every item is one record; content relationships use stable IDs/slugs and evidence IDs. astro check validates the schema; scripts/validate-project-data.mjs checks unique slugs and referential integrity.

| Collection | Count | Required content |
|---|---:|---|
| projects | 14 | ID, name, category, role, summary, delivery state, repository IDs, feature states, stack, limitations and evidence refs |
| experiences | 7 | Organization, role, period, attribution, related projects and evidence |
| cases | 8 | Context, constraints, role, approach, decisions, verification, result, limitations and evidence |
| labs | 4 | Description, topics, learning/source-only state, limitations and evidence |
| capabilities | 5 | Label, evidence-linked projects and state; no arbitrary proficiency score |
| profile | 1 | Approved profile copy, principles, workflow, focus areas and owner-attested evidence |
| education | 1 | Institution, field, cohort and expected graduation; no undated GPA or IELTS self-assessment |
| contact | 1 | Email, public profile links and source note |

Repositories and evidence stay in separate JSON inventories because they are shared references. A sanitized private-source entry can show a generic owner-attested note, but must not contain a URL, source path, branch, commit SHA, media, or repository label. Restricted source status is not exposed as a clickable source.
