## Từ định hướng sản phẩm đến kiến trúc

Luồng mục tiêu của Study2Work là **Learn → Practice → Evidence → Career Profile/CV → Jobs → Applications → Hiring Workflow**. Study và Work hiện có source theo từng package, nhưng bước chia sẻ evidence giữa hai domain vẫn là target kiến trúc, chưa được nối hoặc nghiệm thu.

Kiến trúc repository gồm Study Web (Vue), Study API (FastAPI), Work Web (React), Work API (Express/Prisma), Work Mobile (Flutter), AI API (FastAPI/Ollama) và hai package DB Admin (Angular/FastAPI). Tám package này được tổng hợp từ hai snapshot: phần lớn ở `develop`; Study Web và DB Admin được đối chiếu trên default `main`. Chúng có mức hoàn thiện khác nhau và không phải tám dịch vụ production trong cùng một snapshot.

## Đóng góp và trạng thái source

- Tôi coding codebase và các API #1–8, #48–103. Router source tại snapshot `develop` có route cho 66 Study API IDs; #99–103 hiện ở mức DD, chưa có route trong snapshot này.
- Work API có 21 HTTP operations trong source; điều này không chứng minh mọi màn hình Work đã kết nối hoặc toàn hệ thống chạy end-to-end.
- 83 Study surfaces và 45 Work Mobile views là inventory/design docs. Prototype, local-only và target integration được ghi nhãn riêng.
- Study Web và DB Admin source ở `main`; DB Admin không có trong cây `apps/` đã rà của `develop` và chỉ là công cụ local-only.
